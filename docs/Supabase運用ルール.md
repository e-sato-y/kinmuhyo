# 勤務表サイト　Supabase・鍵の運用ルール

勤務表サイトの開発に参加する人が守るルールです。
作業を始める前に必ず読んでください。わからないことは、自分で判断せずに佐藤に確認してください。

- 管理者：佐藤（sato@r-factory.jp）
- リポジトリ：https://github.com/e-sato-y/kinmuhyo （**公開リポジトリ**。誰でも中身を見られます）

---

## 1. 鍵・トークンの種類と扱い

| 名前 | どこにあるか | 扱い |
|---|---|---|
| anon key（公開用キー） | `config.js` | 公開してよいキー。リポジトリに入っていて問題ありません。データはデータベース側の決まり（RLS）で守っています |
| service_role key / secret key | Supabase の Settings → API | **佐藤だけが扱う。** コード・`config.js`・チャット・メールには絶対に書かない |
| アクセストークン（`sbp_` で始まる） | Supabase の Account → Access Tokens | **人に渡さない・人からもらわない。** 持っている人は、すべてのプロジェクトを操作できてしまいます |
| データベースのパスワード | Supabase の Settings → Database | 佐藤だけが扱う |
| テスト用アカウントのパスワード | 佐藤から個別に連絡 | 本人だけが使う。動作確認のためだけに使う |

## 2. 作業に必要な権限

- 画面（`index.html`）の作業には、**Supabase の管理画面の権限もアクセストークンも必要ありません。**
  必要なのは、動作確認用のテスト用アカウント（ログイン用）だけです。
- Supabase の管理画面を見る必要があるときは、佐藤が **Organization → Team** から本人のアカウントを招待します。
  - 役割は必要な最小限（基本は Read-only、必要なときだけ Developer）にする
  - アカウントの共有はしない（1人1アカウント）
  - 2段階認証（MFA）を有効にする

## 3. やってはいけないこと

1. 鍵・トークン・パスワードを、LINE・Slack・メール・GitHub（コード、Issue、プルリクエスト）・スクリーンショットに載せる
2. service_role key や secret key を、画面のコード（`index.html`・`config.js` など）に書く
3. `.env` など、鍵を書いたファイルをコミットする
4. テーブル・RLS（アクセスの決まり）・`supabase/schema.sql` を、佐藤の承認なしに変更する
5. 本番のデータベースに直接 SQL を実行する
6. 自分のテスト用アカウント以外の勤務表を、入力・提出・差し戻し・削除する
7. `main` ブランチに直接 push する（必ず自分の作業ブランチで作業し、プルリクエストを出す）

## 4. テスト用アカウントの使い方

- 手元の画面（`http://localhost:8000`）も、**公開中のサイトと同じ本番のデータベース**につながっています
- 動作確認は、佐藤が渡したテスト用アカウントで、**自分のテスト用アカウントの勤務表だけ**を使って行います
- 管理者画面の確認には、佐藤が用意する管理者用のテスト用アカウントを使います。管理者アカウントでは他の社員の勤務表も見えるので、**表示する以外の操作（差し戻しなど）は、テスト用アカウントの勤務表に対してだけ**行います
- パスワードは自分で変えてかまいません。人には教えないでください

## 5. push する前の確認

push する前に、変更の中に鍵が入っていないかを確認します。

```bash
git diff feature/new-design --stat
git diff feature/new-design | grep -nE "service_role|sbp_|secret|password"
```

2つ目のコマンドで何か表示されたら、push せずに佐藤に相談してください。
（`config.js` の anon key は、もともと入っているので問題ありません）

## 6. 漏れた・漏れたかもしれないとき

1. **すぐに佐藤へ連絡**（夜間・休日でも連絡してください。消したり隠したりして済ませない）
2. 佐藤が鍵を作り直す（Settings → API で鍵を再発行、Access Tokens で該当トークンを削除）
3. GitHub に push してしまった場合、コミットを消しても履歴に残るため、鍵の作り直しが必要です

## 7. 作業が終わったら

- 佐藤が、Team からの招待の取り消し・テスト用アカウントの削除を行います
- 手元に残ったパスワードのメモなどは削除してください
