# 勤務表サイトのフロントエンド制作のお願い

あなたには、社内向けの「月間勤務表サイト」のフロントエンド（画面）を作ってもらいます。
バックエンド（ログインとデータ保存）は **Supabase** で構築済みで、データベースの形とアクセスの決まりは変えられません。
以下の構想・仕様に沿って、見た目と使いやすさを高めた画面を作ってください。

---

## 1. どういうサイトか

- 小さな会社（社員十数名〜数十名）の **月間勤務表を作成・提出するための社内サイト**。
- 社員は毎月、自分の勤務表（1日ごとの出勤・退勤・休憩・勤務区分・備考）を入力し、月末に「提出」する。
- 管理者（総務担当など）は、全社員の提出状況を一覧で確認し、Excel に出力して給与計算などに使う。
- これまでは1人用の HTML ツールで Excel を作っていた。それを全社員がブラウザから使えるようにしたもの。

### 方向性
- **事務作業を早く・迷わず終わらせる道具**。派手さより、見やすさ・入力のしやすさ・間違えにくさを優先する。
- 利用者はパソコンが得意でない人も含む。**専門用語を使わず、やさしい日本語**で案内する（例：「保存済み 14:32」「赤字の日を直してから提出してください」）。
- パソコンで使うのが中心だが、**スマホでも入力できる**こと（表は横スクロール可）。
- 落ち着いた業務アプリの雰囲気。基調色は紺（#2F5D8A）、Excel 出力ボタンは緑（#217346）。土曜は薄い青、日曜・祝日は薄い赤で行を色分けする。

## 2. 利用者と権限

| 利用者 | できること |
|---|---|
| 一般社員 | 自分の勤務表だけを作成・編集・途中保存・提出・Excel出力。氏名を変更できる |
| 管理者 | 上記に加えて、全社員の勤務表の一覧・閲覧（読み取り専用）・Excel出力（1人ずつ／全員分）・差し戻し |

- 新規登録画面は **作らない**。社員は管理者が Supabase から招待し、招待メールのリンクからパスワードを設定する。
- 権限の制御はデータベース側（RLS）で行われているので、画面は「見せる・隠す」だけでよい。

## 3. 画面構成

### (1) ログイン画面
- メールアドレス・パスワード・「ログイン」ボタン
- 「パスワードを忘れた場合」リンク → 入力済みのメールアドレスに再設定メールを送る

### (2) パスワード設定画面
- 招待メール・再設定メールのリンクから開いたときに表示（URL の `#` 以降に `type=invite` または `type=recovery`、もしくは Supabase の `PASSWORD_RECOVERY` イベント）
- 新しいパスワード（8文字以上）を2回入力して設定 → そのまま勤務表画面へ
- リンクの期限切れなど（URL に `error_description`）は、ログイン画面でわかりやすく案内する

### (3) 勤務表画面（ログイン後のメイン画面）
- 上部：タブ「自分の勤務表」「管理者」（管理者だけ表示）、ログイン中のメールアドレス、ログアウト
- **基本設定エリア**：氏名、対象年月、基本出勤時刻、基本退勤時刻、休憩時間（分）
- **ボタン**：勤務表を作成する／途中保存／提出する／Excel出力
- **保存状態の表示**：「未保存の変更があります」「保存中…」「保存済み 11/3 14:32」「提出済み」「保存できませんでした」
- **勤務表**：1ヶ月分の表。列は 日付・曜日・勤務区分・出勤時刻・退勤時刻・休憩時間・実働時間・備考
- **集計**（表の下）：実働時間の合計、月間勤務日数、有給休暇取得日数（全日◯日・半休◯回）、欠勤日数

### (4) 管理者画面
- 対象年月を選ぶと全社員の一覧を表示：氏名、メールアドレス、状態（未作成／作成中／提出済）、実働時間の合計、勤務日数、有給休暇、欠勤、最終更新、操作
- 操作ボタン：「表示」（下に読み取り専用の勤務表を表示）、「Excel」（その人の分を出力）、「差し戻し」（提出済のときだけ）
- 「全員分をExcel出力」：1ファイルに1人1シートでまとめる
- 計算できない日（赤字の日）がある人には「要確認 ◯件」と表示

## 4. 業務ルール（必ずこの通りに動くこと）

### 勤務表の作成
- 対象年月の1日〜月末まで1行ずつ作る。
- **土日・祝日は「休日」**、それ以外は「出勤」で、基本出勤・退勤時刻と休憩時間を入れる。
- 祝日は外部サービスを使わず計算で求める（2022年以降のルール）：元日、成人の日（1月第2月曜）、建国記念の日、天皇誕生日（2/23）、春分の日、昭和の日、憲法記念日、みどりの日、こどもの日、海の日（7月第3月曜）、山の日（8/11）、敬老の日（9月第3月曜）、秋分の日、スポーツの日（10月第2月曜）、文化の日、勤労感謝の日、**振替休日**、**国民の休日**。
  - 春分日：`floor(20.8431 + 0.242194*(年-1980) - floor((年-1980)/4))`
  - 秋分日：`floor(23.2488 + 0.242194*(年-1980) - floor((年-1980)/4))`
- 祝日名は勤務区分の下に小さく表示する。
- すでに作成済みの月で作り直すときは確認を出す。
- 作成時の基本時刻は、社員情報（profiles）の既定値として保存し、次の月の初期値にする。

### 勤務区分
`出勤`・`午前休`・`午後休`・`休日`・`有給休暇`・`欠勤` の6種類。
- 時刻を入力するのは `出勤`・`午前休`・`午後休` だけ（それ以外は時刻・休憩の欄を入力不可にして空にする）。
- 区分を変えたときの自動入力（基本設定が 9:00〜18:00・休憩60分の例）：
  - 出勤 → 9:00〜18:00、休憩60分
  - 半日分 ＝ (退勤 − 出勤 − 休憩) ÷ 2（この例では240分）
  - 午後休 → 出勤時刻から半日分（9:00〜13:00）、休憩0分
  - 午前休 → 退勤時刻までの半日分（14:00〜18:00）、休憩0分

### 実働時間と集計
- 実働時間 ＝ 退勤 − 出勤 − 休憩。
- 計算できない日は赤字で理由を表示し、合計に含めない：「時刻を入力」「退勤が出勤より前」「休憩が長すぎます」。
- 月間勤務日数 ＝ 出勤・午前休・午後休の日数。
- 有給休暇取得日数 ＝ 有給休暇の日数 ＋ (午前休 ＋ 午後休) × 0.5。
- 備考は自由入力＋候補（「在宅勤務」）から選択できる。

### 途中保存
- 入力が止まって **3秒後に自動保存**。「途中保存」ボタンで即保存。
- 保存は1つずつ順番に行い、同時に2つ走らないようにする。保存中にさらに変更されたら「未保存」のままにする。
- 未保存の変更があるままページを閉じようとしたら確認を出す。タブを切り替えたとき（`visibilitychange`）も保存する。
- 対象年月を切り替える前に保存し、保存に失敗したら切り替えない。

### 提出・差し戻し
- 赤字の日が残っていると提出できない。
- 提出前に確認を出す。提出後は本人は編集できない（全欄とボタンを無効化し、そう案内する）。
- 管理者が差し戻すと「作成中」に戻り、本人が再び編集できる。

### Excel 出力（ExcelJS 4.4.0 を使用。`vendor/exceljs.min.js` に同梱済み）
- 1行目：「2026年11月 勤務表」、2行目：「氏名：◯◯」、3行目：「基本勤務時間：9:00〜18:00（休憩60分）」、4行目：見出し（固定表示）
- 5行目から1日1行。日付は本物の日付（`m/d`）、時刻は Excel の時刻値（`h:mm`）、休憩は `0"分"`
- 実働時間は Excel の計算式（`IF(OR(D5="",E5=""),"",E5-D5-F5/1440)`、表示 `[h]:mm`）
- 備考欄は「祝日名／備考」をつなげて入れる。勤務区分と備考にはプルダウン（入力規則）を付ける
- 土曜は青、日曜・祝日は赤で色分け。罫線あり。A4縦・横1ページに収まる印刷設定
- 表の2行下に集計（Excel の計算式 SUM・COUNTIF で）。有給の行に「※午前休・午後休は0.5日」
- ファイル名：`勤務表_2026年11月_氏名.xlsx`（全員分は `勤務表_2026年11月_全員.xlsx`）

## 5. バックエンド（Supabase）の仕様 ※変更不可

接続先は `config.js` に定義済み（`SUPABASE_URL` と `SUPABASE_ANON_KEY` をグローバル定数として読み込む）。
Supabase JS は v2（`@supabase/supabase-js@2`）を使う。

### テーブル `profiles`（社員1人1行。招待時に自動作成）
| 列 | 型 | 説明 |
|---|---|---|
| id | uuid | auth.users の id |
| email | text | |
| full_name | text | 氏名（本人が変更可） |
| is_admin | boolean | 管理者なら true（本人は変更不可） |
| default_start / default_end | text | 基本出勤・退勤時刻（"09:00" 形式、本人が変更可） |
| default_break | integer | 休憩（分、本人が変更可） |

### テーブル `timesheets`（社員1人・1ヶ月1行。`unique(user_id, year, month)`）
| 列 | 型 | 説明 |
|---|---|---|
| user_id | uuid | 社員 |
| year / month | integer | 年・月 |
| settings | jsonb | `{ year, month, startTime: "09:00", endTime: "18:00", breakMinutes: 60 }` |
| rows | jsonb | 1日ごとの配列（下記） |
| status | text | `draft`（作成中）または `submitted`（提出済） |
| updated_at | timestamptz | 自動更新 |

`rows` の1要素：
```json
{ "month": 11, "day": 3, "weekday": 2, "holidayName": "文化の日",
  "type": "休日", "start": "", "end": "", "breakMinutes": 0, "remark": "" }
```
（weekday は 0=日〜6=土。既存データとの互換のため、この形は変えないこと）

### 主な操作
- 保存：`timesheets` に `upsert`（`onConflict: "user_id,year,month"`、status は `draft`）
- 読み込み：`user_id`・`year`・`month` で `maybeSingle()`
- 提出：`update({ status: "submitted" })` → `.select()` で1行更新されたか確認
- 差し戻し（管理者）：`update({ status: "draft" })`
- 管理者一覧：`profiles` 全件 と その月の `timesheets` 全件を取得して結合

### アクセスの決まり（RLS）
- 本人は自分の行だけ読み書きできる。提出済（submitted）の行は本人は更新できない。
- 管理者は全員分を読め、status を更新できる。
- 削除はできない。未ログインでは何も読めない。

## 6. 技術的な制約

- 公開先は **Render の Static Site**（GitHub に push すると反映）。サーバー側の処理は持てない。
- 現在はビルドなしの素の HTML/CSS/JavaScript（`index.html` 1ファイル＋`config.js`＋`vendor/exceljs.min.js`）。
  - フレームワーク（React + Vite など）を使ってもよいが、その場合は Render の Build Command と Publish Directory（現在は `mkdir -p dist && cp -r index.html config.js vendor dist/` と `dist`）も合わせて示すこと。
  - 迷ったら、今の構成（ビルドなし）のままを推奨。
- 外部ライブラリは CDN からバージョン固定で読み込む。
- service_role キーなどの秘密情報は絶対に画面側に書かない（anon key だけを使う）。
- 氏名など利用者が入力した文字を画面に出すときは、HTML として解釈されないようにする（XSS 対策）。

- 管理者画面で、未提出の人がすぐわかる表示（並べ替え・絞り込みなど）
- スマホでの入力のしやすさ
